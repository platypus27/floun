# PDF report formatting evidence

Before and after page renders for the PDF report formatting fix. The PDF is
generated by `floun/src/components/reportgen/pdfService.tsx` on top of the
layout engine in `pdfLayout.ts`. Reports were produced by scanning the local
synthetic fixture (`floun/fixtures/crypto-readiness.html`) and a synthetic
60-finding stress set with long URLs and hashes through the real report
pipeline (`buildReportContent` -> `generatePDFReport`).

## Defects and fixes

| Defect | Fix |
| --- | --- |
| Long URLs and hashes drew past the right margin and were clipped at the page edge (`wrapText` only broke at spaces). | `wrapLineToWidth` character-breaks overlong words, prefers breaking at `/ - . ? & =` punctuation, and packs the first fragment onto the current line. |
| All newlines were collapsed, so the appendix and readiness analysis rendered as walls of text with findings running together. | `sanitizeReportText` preserves paragraph breaks; findings are joined with blank lines; the layout engine separates paragraphs vertically. |
| Every section was forced onto its own page, leaving pages 90% empty (15 pages for a small scan). | Sections flow continuously; a new page starts only when the next line does not fit. |
| Section headings could be stranded at the bottom of a page. | Headings keep with at least two following body lines before a page break is allowed. |
| No page numbers, header, or footer on any page. | Every page after the cover carries a footer rule, report title, and `Page X of Y`. |
| Text was pure black with no brand colours. | Headings use the Teal light-theme primary `#0F6A6C`, body `#22423A`, muted footer `#4C6A60`, and a `#EEE2C8` rule. |
| Cover title overlapped the logo; the Table of Contents had no page numbers. | Cover is laid out sequentially (no overlap) and the TOC uses dotted leaders with real page numbers recorded during layout. |
| Appendix group titles (`JavaScript Results:`) ran inline with content. | Group titles render as bold Teal sub-headings. |
